Google Photos · Privacy policy

Privacy, in plain language

DiAndré Art Manager Local uses Google Photos to help an artist bring selected photographs and videos into an independently managed art portfolio. This page explains what the integration accesses, where copies are kept and how publication works.

Effective: 13 November 2026 · Applies to: the local ARTS Manager Google Photos Picker integration, not Google's own services.

1. Which information is accessed?

The application requests the OAuth scope https://www.googleapis.com/auth/photospicker.mediaitems.readonly. It can create a Picker session and list/download the media that the authorised Google user explicitly selects. Imported data may include the file contents, filename, media type and original creation time provided by Google. It does not request permission to browse the whole Google Photos library.

2. What is the information used for?

Only to provide the artist-requested import feature: creating gallery artwork entries, or archiving studies, working sketches and photographs as supporting Studio Assets. The integration does not sell user data, use it to target advertisements, or use Google Photos information to train artificial-intelligence models.

3. Where are data and credentials stored?

OAuth client configuration, access tokens, refresh tokens and temporary Picker-session records are saved locally on the artist’s Mac under .art-private/google-photos/, outside the public website directory. Studio Assets and their local metadata are stored under .art-private/studio/. Ordinary gallery artwork copies are saved to the Mac's art/assets/works/ directory. No remote account database is operated by this integration.

4. When does anything become public?

Google authorization and selecting media do not publish the media. If the artist chooses to publish gallery artworks or makes supporting Studio Assets publicly visible through “See related”, the selected copies and relevant gallery metadata may be committed and pushed to the public GitHub repository and served on the DiAndré Art website. Public Git history and caches may retain copies even after later removal from the current gallery.

Public-file warning: A file placed in a public repository is not private merely because it is unlinked from the website’s navigation. Only explicitly approved media should be published.

5. How long is information retained?

The software does not impose an automatic deletion date for imported artwork or Studio files. Local tokens are kept for reconnection until the account is disconnected or the files are deleted. Picker sessions are temporary and cleared when cancelled or successfully completed. Backups and published Git history may retain older copies and require separate removal.

6. Your choices, disconnection and deletion

  1. Stop future access: In ARTS Manager, open Upload → From Google Photos → Configure Google Photos → Disconnect Google Photos. You can also revoke access in your Google Account’s third-party connections.
  2. Delete imported supporting media: Remove an unwanted item from the Studio Assets library. This changes the local archive; check public outputs and Git history separately if it had been published.
  3. Remove a published artwork: Contact the artist/maintainer to remove the site copy, public references and, where necessary, address published Git history. Hiding an artwork from the gallery does not remove its public file.
  4. Ask questions or request deletion: Contact the maintainer through the developer’s GitHub profile. Do not post private images or credentials in a public issue.

7. Sharing and safeguards

Selected files move from Google Photos to the locally running software on the artist’s Mac. They are shared publicly through GitHub and the art website only if the artist separately chooses to publish them. The software stores OAuth credentials outside the public site, restricts import requests to Google-provided media addresses and supports disconnecting the Google account. The artist is responsible for securing local backups and the computer.

8. Google policies

Use of Google Photos data in this integration is intended to comply with the Google Photos API User Data and Developer Policy and the Google API Services User Data Policy, including their Limited Use requirements. Google applies its own policies to information held in Google Photos; those services are outside this site's control.

9. Changes

We will update this notice if the integration's permissions, data handling or publication workflow changes. The date at the top indicates the effective edition.
